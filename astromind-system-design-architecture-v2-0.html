⚠️ v2.0 Architecture Change Notice This document supersedes v1.0. The original 3-layer architecture (Presentation → Application → Data) has been expanded to a 5-layer architecture incorporating the IBM ecosystem. The Presentation, AI Core, and Data layers are preserved. The LLM layer is upgraded from OpenAI to IBM Granite via watsonx.ai. Two new layers have been added: Orchestration (LangChain) and Knowledge (Docling + RAG). ContextForge / MCP is deferred to Phase 2.
1. 🗺️ Architecture Overview

AstroMind v2.0 follows a 5-layer architecture with clear separation between UI, orchestration, AI core processing, LLM inference, knowledge retrieval, and data persistence.

Layer 1
🖥️ Presentation Layer — Streamlit

Chat interface, mood dashboard, alert panel, session summary view. Unchanged from v1.0.

Layer 2
⚙️ Orchestration Layer — LangChain + LangFlow NEW

Manages conversation memory, LLM chains, structured output parsing, and RAG context injection. Replaces hand-rolled conversation.py, client.py, and parser.py.

Layer 3
🧠 Application / AI Core Layer — Python

Mood Detection Engine, Health Score Calculator, Risk Classifier, Coping Strategy Selector, Summary Generator. Logic preserved; wiring delegated to LangChain.

Layer 4
🤖 LLM Layer — IBM Granite via watsonx.ai UPDATED

Primary: ibm/granite-3-8b-instruct. Replaces OpenAI GPT-4o. Enterprise-grade, privacy-first, IBM Cloud hosted.

Layer 5
📚 Knowledge Layer — Docling + ChromaDB NEW

Ingests NASA PDF documents (STD-3001, HRP Behavioral Health reports) via Docling, stores chunks in ChromaDB, injects relevant context into each LLM call via RAG.

Layer 6
🗃️ Data Layer — SQLite

Sessions, mood scores, messages, alerts, summaries. Unchanged from v1.0.

3. 🔄 Core Data Flow
3.1 Conversation Flow (Revised)
Astronaut types message │ ▼ [Streamlit UI] → sends message to Orchestration Layer │ ▼ [LangChain] → retrieves conversation history from ConversationBufferMemory │ ▼ [ChromaDB RAG] → fetches top-3 relevant NASA doc chunks │ ▼ [LangChain LLMChain] → builds prompt: system + history + RAG context + user message │ ▼ [IBM Granite via watsonx.ai] → returns structured JSON response │ ▼ [StructuredOutputParser + Pydantic] → validates {mood, score, risk, response, coping} │ ├──→ [Mood Engine] → extracts mood + score ├──→ [Risk Classifier] → classifies LOW/MEDIUM/HIGH ├──→ [Coping Selector] → maps strategy ├──→ [SQLite] → persists message + mood score │ ▼ [Streamlit UI] → renders response + updates dashboard
3.2 Session End Flow (unchanged)
User ends session │ ▼ [Summary Generator] → sends full transcript to Granite via summarization chain │ ▼ [SQLite] → stores summary + final score + risk level │ ▼ [Streamlit] → displays session summary in st.expander
3.3 Knowledge Ingestion Flow — NEW
NASA PDF files placed in knowledge/docs/ │ ▼ [Docling] → parses PDF → extracts clean structured text │ ▼ [LangChain TextSplitter] → chunks text into ~500 token segments │ ▼ [ChromaDB] → embeds chunks → stores vector index │ ▼ (at query time) [RAG Retriever] → similarity search on astronaut message │ ▼ Top-3 chunks injected into Granite prompt as grounding context
4. 🧠 System Prompt Architecture (updated for RAG)

The system prompt now includes a 5th section for RAG context injection:

S1
Persona & Role Definition
Who AstroMind is, its tone, its mission aboard a long-duration space flight
S2
Behavioral Rules
What it must/must not do — warmth, no diagnosis, emergency protocol triggers
S3
Mood Detection Instructions
Classify mood: CALM / STRESSED / ANXIOUS / FATIGUED / DEPRESSED. Score 0–100. Risk: LOW/MEDIUM/HIGH
S4
NASA Knowledge Context NEW
Injected at runtime by RAG retriever — relevant excerpts from NASA-STD-3001 and HRP Behavioral Health docs grounding the response in evidence-based protocols
S5
Output Format (JSON)
Structured JSON: {mood, score, risk_level, response, coping_strategy} — parsed by StructuredOutputParser
SYSTEM_PROMPT = """ ## ROLE You are AstroMind, an empathetic AI psychological companion aboard a long-duration space mission. You provide emotional support, active listening, and evidence-based coping strategies to crew members. ## BEHAVIORAL RULES - Always respond with warmth, clarity, and calm - Never diagnose medical or psychiatric conditions - Never minimize the astronaut's feelings - If extreme distress or suicidal ideation is detected, always include emergency protocol reminder - Keep responses under 100 words unless more depth is needed ## MOOD DETECTION After each astronaut message, assess their emotional state. Classify mood as one of: CALM, STRESSED, ANXIOUS, FATIGUED, DEPRESSED Assign a wellness score from 0 (crisis) to 100 (thriving) Classify risk as: LOW, MEDIUM, or HIGH ## NASA KNOWLEDGE CONTEXT {rag_context} Use the above NASA-grounded evidence to inform coping strategies and risk thresholds. If no context is provided, use general best practices. ## OUTPUT FORMAT Always respond in this exact JSON format: { "mood": "STRESSED", "score": 45, "risk_level": "MEDIUM", "response": "Your empathetic response text here...", "coping_strategy": "Try the 4-7-8 breathing technique..." } """
